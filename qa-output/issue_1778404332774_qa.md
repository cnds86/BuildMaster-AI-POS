## Bug #1: `/api/ai/chat` Returns HTML Instead of JSON (Critical)

### Severity: HIGH
### Location: `server/routes/ai.ts` + `server/index.ts`

### Reproduction

```bash
# No AI key configured — .env has GEMINI_API_KEY=empty
curl -s -X POST http://localhost:3006/api/ai/chat \
  -H "Content-Type: application/json" \
  -d '{"type":"construction_estimate","query":"build a wall","inventory":[]}'
```

### Actual Response
```json
{"error":"GEMINI_API_KEY not set"}
```
✅ Actually returns JSON — but only because the guard short-circuits before calling `aiChat()`.

### Problem Scenario: When Guard Fails or `set.status` is Set with HTML Fallback

The guard at lines 259-264 of `ai.ts` returns plain object `{ error: "..." }`:
```typescript
if (PROVIDER === 'gemini' && !GEMINI_API_KEY) return { error: 'GEMINI_API_KEY not set' }
```

However, in the `catch` block (lines 270-273):
```typescript
} catch (err) {
  console.error(`[AI /chat] provider=${PROVIDER} type=${req.type}`, err)
  set.status = 502
  return { error: `AI request failed (${PROVIDER})` }
}
```

When the Elysia server has an unhandled exception OR when a route throws an error mid-flight, the `.get('*', ...)` catch-all at line 224 of `server/index.ts` intercepts it and returns `Bun.file('./dist/index.html')` — an HTML page — instead of a JSON error response.

### Root Cause
The catch-all `.get('*', ...)` at the bottom of `server/index.ts` serves the SPA for **all unmatched routes**, but it's placed AFTER the API routes. However, when the server throws a 500-level response with no body, the client may receive the HTML page instead of JSON if the response isn't properly formatted.

### Evidence: Non-existent route returns HTML
```bash
curl -s http://localhost:3006/api/nonexistent-route
# Returns full HTML SPA page (<!DOCTYPE html>...)
```

### Fix Required
The `catch` block in `/api/ai/chat` should explicitly set `Content-Type: application/json` and return a proper Response object:

```typescript
} catch (err) {
  console.error(`[AI /chat] provider=${PROVIDER} type=${req.type}`, err)
  set.status = 502
  return { error: `AI request failed (${PROVIDER})` }
}
```

Should be:
```typescript
} catch (err) {
  console.error(`[AI /chat] provider=${PROVIDER} type=${req.type}`, err)
  set.status = 502
  set.headers['Content-Type'] = 'application/json'
  return new Response(JSON.stringify({ error: `AI request failed (${PROVIDER})` }), {
    headers: { 'Content-Type': 'application/json' },
  })
}
```

Or better yet, add an error handler plugin in Elysia that consistently formats all error responses as JSON.

## Bug #2: `/api/auth/change-password` Endpoint Missing

### Severity: CRITICAL  
### Location: `server/plugins/auth.ts` — **NOT IMPLEMENTED**

### Frontend Call
```typescript
// components/UserProfile.tsx:61
const res = await fetch('/api/auth/change-password', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ currentPassword, newPassword }),
  credentials: 'include',
})
```

### Expected Backend Handler
```typescript
.post('/change-password', async ({ body, jwt: jwtFn, cookie: { auth_token }, set }: any) => {
  // 1. Verify JWT token
  // 2. Validate currentPassword against stored hash
  // 3. Hash newPassword with bcrypt
  // 4. Update users table
  // 5. Return { success: true }
})
```

### Current State
- Route does NOT exist in `server/plugins/auth.ts`
- Frontend will receive `404` or HTML response
- **User cannot change password through the UI**

### Fix Required
Add the endpoint to `server/plugins/auth.ts`:

```typescript
.post('/change-password', async ({ body, jwt: jwtFn, cookie: { auth_token }, set }: any) => {
  const token = auth_token?.value
  if (!token) { set.status = 401; return { error: 'Authentication required' } }
  
  let payload: any
  try { payload = await (jwtFn as any).verify(token) } 
  catch { set.status = 401; return { error: 'Invalid token' } }
  
  const { currentPassword, newPassword } = body as { currentPassword: string; newPassword: string }
  if (!currentPassword || !newPassword) {
    set.status = 400; return { error: 'Both passwords are required' }
  }
  if (newPassword.length < 6) {
    set.status = 400; return { error: 'New password must be at least 6 characters' }
  }
  
  const user = await db.selectFrom('users')
    .select(['id', 'password_hash'])
    .where('id', '=', payload.sub)
    .executeTakeFirst()
  
  if (!user) { set.status = 404; return { error: 'User not found' } }
  
  const valid = await bcrypt.compare(currentPassword, user.password_hash)
  if (!valid) { set.status = 403; return { error: 'Current password is incorrect' } }
  
  const hash = await bcrypt.hash(newPassword, 10)
  await db.updateTable('users').set({ password_hash: hash }).where('id', '=', payload.sub).execute()
  
  return { success: true, message: 'Password changed successfully' }
}, {
  body: t.Object({
    currentPassword: t.String({ minLength: 1 }),
    newPassword: t.String({ minLength: 6 }),
  }),
})
```
